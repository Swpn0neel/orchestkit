Stop hook: npm audit at most once a day

The security scan that runs when a session stops used to call npm audit --json every time the working tree was dirty. That is a registry round trip per stop, and with many sessions open it adds up to real CPU and network load.

What changes

stop/security-scan-aggregator.ts now keeps a small stamp file per project in the temp directory (named from a hash of the project path). If the stamp is younger than 24 hours, the audit is skipped and reported as "not run". The stamp is written before the audit starts, so a timeout or failure also holds off an immediate retry. The other scans (pip-audit, semgrep, bandit, secret scan) are unchanged.

Tests

Two tests in security-scan-aggregator.test.ts put a fake npm first on PATH and count real calls: a second stop inside 24 hours runs nothing, and a stamp older than 24 hours lets the audit run again. Against the unchanged source they fail, so they test the change.
